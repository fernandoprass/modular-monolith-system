# Core API

Core API is the main host for modular monolith mode.

It lives in:

```text
src/00.Core/Core.API
```

Core API is not a business module.

It does not own domain rules.

It starts one HTTP application that loads module APIs into the same process.

---

## 1. Purpose

Core API lets the system run as one application.

It loads:
- IAM API
- Sentinel API
- Courier API

This gives one HTTP port for all module endpoints.

Current URLs:

| Mode | URL |
| :--- | :--- |
| Local HTTPS | `https://localhost:4050` |
| Docker | `http://localhost:5050` |

Swagger:

```text
https://localhost:4050/swagger/index.html
```

Docker Swagger:

```text
http://localhost:5050/swagger/index.html
```

---

## 2. What Core API Does

Core API configures common host concerns:
- Controllers
- Swagger
- Authentication
- Authorization
- Exception handling
- Shared infrastructure
- Module infrastructure

It exposes this health endpoint:

```text
GET /api/v1/core/health
```

---

## 3. Controller Loading

Controllers stay in their module API projects.

Core API loads them through ASP.NET Core Application Parts.

This means:
- IAM controllers stay in `IAM.API`.
- Sentinel controllers stay in `Sentinel.API`.
- Courier controllers stay in `Courier.API`.
- Core API does not copy controllers.

---

## 4. Module Registration

Each module API exposes one reusable registration method.

Current methods:

```csharp
builder.Services.AddIamModule(builder.Configuration);
builder.Services.AddSentinelModule(builder.Configuration);
builder.Services.AddCourierModule(builder.Configuration);
```

Core API calls all of them.

Standalone module APIs call their own method.

This keeps both deployment modes using the same dependency setup.

---

## 5. Dependency Rule

Core API can reference module API projects.

Business modules should not reference Core API.

Allowed:

```text
Core.API -> IAM.API
Core.API -> Sentinel.API
Core.API -> Courier.API
```

Not allowed:

```text
IAM -> Core.API
Sentinel -> Core.API
Courier -> Core.API
```

Core API is an orchestration host only.

It should not contain:
- Business services
- Domain entities
- Module-specific constants
- Copied controllers

---

## 6. Future Modules

When adding a new module:

1. Keep the module independently runnable.
2. Add a reusable `Add{Module}Module` registration method.
3. Make the standalone API call that method.
4. Reference the module API project from Core API.
5. Add the module controller assembly as an Application Part.
6. Add Docker configuration if needed.

The module should still work without Core API.
