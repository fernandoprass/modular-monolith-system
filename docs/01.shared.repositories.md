# Shared Infrastructure Repository

This document explains the shared repository pattern.

The goal is simple:
- Keep data access consistent.
- Avoid repeating basic EF Core CRUD code.
- Keep Application services testable.

---

## Main Files

Contracts:
- `src/01.Shared/Shared.Domain/Interfaces/IBaseRepository.cs`

Implementation:
- `src/01.Shared/Shared.Infrastructure/Repositories/BaseRepository.cs`

Dependency injection:
- `src/01.Shared/Shared.Infrastructure/SharedDependencyInjection.cs`

## Base Interfaces

There are two base interfaces.

Generic ID:

```csharp
public interface IBaseRepository<T, TId> where T : Entity<TId>
```

Guid ID shortcut:

```csharp
public interface IBaseRepository<T> : IBaseRepository<T, Guid> where T : Entity
```

Use the Guid version for most entities.

Use the generic version only when the entity ID is not Guid.

---

## Base Methods

`IBaseRepository` exposes write-side operations:

| Method | Purpose |
| --- | --- |
| `GetByIdAsync` | Load one entity by ID. |
| `AddAsync` | Add a new entity to EF tracking. |
| `Update` | Mark an entity as updated. |
| `DeleteAsync` | Remove an entity by ID if found. |
| `ExistsAsync` | Check if an entity exists without loading it. |

`Update` is synchronous by design.

`SaveChangesAsync` is not in the repository.

Saving belongs to Unit of Work.

---

## BaseRepository

`BaseRepository<T, TId>` wraps:
- `DbContext`
- `DbSet<T>`

It implements common EF Core behavior.

It is safe for simple CRUD.

For business entities, prefer a module-specific repository interface.

This keeps the Application layer explicit.

---

## Module-Specific Repository

Domain interface:

```csharp
public interface IUserRepository : IBaseRepository<User>
{
   Task<User?> GetByEmailAsync(string email, CancellationToken cancellationToken = default);
}
```

Infrastructure implementation:

```csharp
public class UserRepository(IamDbContext dbContext)
   : BaseRepository<User>(dbContext), IUserRepository
{
   public async Task<User?> GetByEmailAsync(
      string email,
      CancellationToken cancellationToken = default)
   {
      return await _dbSet.SingleOrDefaultAsync(
         user => user.Email == email,
         cancellationToken);
   }
}
```

The service depends on `IUserRepository`.

It does not depend on `BaseRepository<User>`.

## Query Repositories

Write repositories return entities.

Query repositories return DTOs.

Use query repositories for:
- Search screens.
- List endpoints.
- Details endpoints.
- Read-only projections.

Rules:
- Use `AsNoTracking()`.
- Return DTOs.
- Keep filters in search request DTOs.
- Do not return EF entities from query APIs.

Example:

```csharp
public interface IUserQueryRepository
{
   Task<UserDto?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default);
}
```

## Unit of Work

Repositories track changes.

Unit of Work saves changes.

Example:

```csharp
await _unitOfWork.Users.AddAsync(user, cancellationToken);
await _unitOfWork.SaveChangesAsync(cancellationToken);
```

Why:
- One transaction boundary.
- One place for audit fields.
- Clear service orchestration.

---

## Ownership Checks

Repository should not enforce tenant ownership.

Application services enforce ownership.

Use `ExecuteIfUserOwnsAsync`.

Example:

```csharp
return await ExecuteIfUserOwnsAsync(entity.OrganizationId, async ct =>
{
   _unitOfWork.Users.Update(entity);
   await _unitOfWork.SaveChangesAsync(ct);
   return Result.Success();
}, cancellationToken);
```

This keeps multi-tenancy rules visible in application flow.

---

## What Repositories Should Not Do

Repositories should not:
- Publish events.
- Build audit logs.
- Contain business validation.
- Return `Result`.
- Read HTTP context.
- Call other modules.

Services and orchestrators do that work.

---

## Testing

Application tests should mock repository interfaces.

Do not test EF Core behavior in service unit tests.

Repository integration tests can use a real database later when needed.

For service tests:
- Mock repository return values.
- Verify unit of work calls.
- Verify cache invalidation.
- Verify audit publishing when the action succeeds.
