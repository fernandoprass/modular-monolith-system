# IAM Authorization

IAM uses role-based permissions.

JWT tokens carry role IDs.
They do not carry permission lists.

## Permission Codes

Permission codes follow:

```text
iam.group.action
```

Examples:

```text
iam.users.list
iam.users.view
iam.roles.assign
```

Use `IamPermission` constants.
Do not hardcode permission strings in controllers.

## RequirePermissionAttribute

Controllers use `RequirePermissionAttribute`.

The attribute must implement:

- `AuthorizeAttribute`
- `IAuthorizationRequirement`
- `IAuthorizationRequirementData`

This lets ASP.NET add the permission requirement to the authorization policy.
If the handler is not called, check this attribute first.

## PermissionAuthorizationHandler

The handler flow:

1. Reject unauthenticated users.
2. Allow `IsSystemAdmin`.
3. Read role IDs from JWT claims.
4. Load permissions for each role.
5. Use cached role permissions when available.
6. Check the required permission code.

## Cache

Role permissions are cached by role ID.

When role-permission assignments change, remove that role from cache.

## Self Access

Self-access endpoints should not require permissions.

Example:

```text
GET /api/v1/iam/users/me
```

Permissions protect access to other users, lists, and admin actions.

## Required Updates

When adding a protected endpoint, update:

- `IamPermission`
- `SeederPermissions`
- `SeederRolePermissions`
- Bruno files
- Unit tests when authorization behavior changes
