# IAM Entities

In Domain-Driven Design (DDD), entities are objects with identity and lifecycle. They represent business concepts that can change over time.

The IAM module manages organizations, users, roles, and permissions. These entities live in the Domain layer and should keep business rules close to the data they protect.

## User Entity

The `User` entity represents a person who can sign in and use the system.

### Properties

- **Id** (Guid): Unique identifier.
- **Name** (string): User full name.
- **Email** (string): Login and communication email. It is stored lowercase and trimmed.
- **PasswordHash** (string): Hashed password. Plain text passwords are never stored.
- **IsActive** (bool): Indicates if the user can use the system.
- **IsSystemAdmin** (bool): Allows bypassing permission checks.
- **IsSupportUser** (bool): Marks support users.
- **IsOrganizationAdmin** (bool): Marks organization-level admin users.
- **NumFailedLoginAttempts** (int): Number of failed login attempts.
- **EmailVerifiedAt** (DateTime?): Date when the email was confirmed.
- **LastLoginAt** (DateTime?): Date of the last successful login.
- **PasswordExpiresAt** (DateTime?): Password expiration date.
- **LockedOutUntil** (DateTime?): Lockout expiration date.
- **Language** (string): Preferred user language, normalized by `LanguageOptions`.
- **OrganizationId** (Guid): Organization that owns the user.
- **Organization** (navigation property): Related `Organization`.
- **UserRoles** (IReadOnlyCollection<UserRole>): Roles assigned to the user.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

### Behavior

- `Create` creates a normal user and normalizes email and language.
- `CreateOrganizationAdmin` creates a user and marks it as organization admin.
- `Update` changes name, active state, and language.
- `UpdatePassword` changes the password hash and expiration date.
- `UpdateOrganizationAdmin` changes the organization admin flag.
- `UpdateSupportUser` changes the support user flag.
- `RegisterLastSuccessfullyLogin` stores the login date and clears failed attempts.
- `RegisterFailedLoginAttempt` increments failed attempts and can lock the user.
- `AddRole`, `RemoveRole`, and `ClearRoles` manage assigned roles.

## Organization Entity

The `Organization` entity represents a tenant, company, or person that owns users and roles.

### Properties

- **Id** (Guid): Unique identifier.
- **Type** (OrganizationType): Organization type, such as company or person.
- **Code** (string): Business code for the organization.
- **Name** (string): Organization name.
- **Description** (string?): Optional description.
- **DefaultLanguage** (string): Default organization language, normalized by `LanguageOptions`.
- **IsActive** (bool): Indicates if the organization is active.
- **Users** (ICollection<User>): Users that belong to the organization.
- **Roles** (ICollection<Role>): Organization-specific roles.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

### Behavior

- `Create` creates an organization and normalizes the default language.
- `Update(code)` changes the organization code.
- `Update(name, description, isActive, defaultLanguage)` changes editable organization data.

## Role Entity

The `Role` entity groups permissions. A role can be global or organization-specific.

### Properties

- **Id** (Guid): Unique identifier.
- **Name** (string): Role name.
- **Description** (string): Role description.
- **IsDefault** (bool): Indicates if this role is assigned by default.
- **IsActive** (bool): Indicates if the role is active.
- **OrganizationId** (Guid?): Null for global roles, or organization ID for tenant roles.
- **Organization** (navigation property): Related organization for tenant roles.
- **RolePermissions** (IReadOnlyCollection<RolePermission>): Permissions assigned to the role.
- **UserRoles** (IReadOnlyCollection<UserRole>): Users assigned to the role.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

### Behavior

- `Create` creates a role.
- `Update` changes role data.
- `AddPermission`, `RemovePermission`, and `ClearPermissions` manage assigned permissions.

## Permission Entity

The `Permission` entity represents an allowed action.

### Properties

- **Id** (Guid): Unique identifier.
- **Module** (string): Module name, such as `iam`.
- **Resource** (string): Resource name, such as `users`.
- **Action** (string): Action name, such as `create`.
- **Code** (string): Lowercase `{module}.{resource}.{action}` code.
- **Title** (string): Display title.
- **Description** (string): Display description.
- **IsActive** (bool): Indicates if the permission is active.
- **RolePermissions** (IReadOnlyCollection<RolePermission>): Roles that use the permission.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

### Behavior

- `Create` creates a permission and builds the permission code.
- `Update` changes permission data and rebuilds the permission code.
- `BuildCode` creates the normalized permission code.

## UserRole Entity

The `UserRole` entity links users to roles.

### Properties

- **Id** (Guid): Unique identifier.
- **UserId** (Guid): User ID.
- **RoleId** (Guid): Role ID.
- **StartsAt** (DateTime): Date when the role assignment starts.
- **ExpiresAt** (DateTime?): Optional role expiration date.
- **User** (navigation property): Related user.
- **Role** (navigation property): Related role.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

### Behavior

- `Create` creates a role assignment.
- `UpdateValidity` changes the start and expiration dates.

## RolePermission Entity

The `RolePermission` entity links roles to permissions.

### Properties

- **Id** (Guid): Unique identifier.
- **RoleId** (Guid): Role ID.
- **PermissionId** (Guid): Permission ID.
- **Role** (navigation property): Related role.
- **Permission** (navigation property): Related permission.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

## Relationships

- **Organization to User**: One organization can have many users. Each user belongs to one organization.
- **Organization to Role**: One organization can have many tenant roles. Global roles have no organization.
- **User to Role**: Many-to-many through `UserRole`.
- **Role to Permission**: Many-to-many through `RolePermission`.

## Design Principles

- **Identity**: Entity IDs are generated once and should not change.
- **Audit Trail**: Audited entities store creation and update metadata.
- **Security**: Passwords are stored only as hashes.
- **Language Normalization**: User and organization languages are normalized by `LanguageOptions`.
- **Tenant Ownership**: Users and tenant roles are scoped to organizations.
- **Encapsulated Collections**: Role and permission assignments are exposed as read-only collections.
- **Permission Codes**: Permission codes use lowercase `{module}.{resource}.{action}`.
