# Courier Entities

In Domain-Driven Design (DDD), entities are objects with identity and lifecycle. They represent business concepts that can change over time.

The Courier module stores user communication data. It can create emails and in-app notifications from the same template translation. Today, Courier runs on the same API host as the other modules, but it can be deployed behind a different endpoint later.

## Email Entity

The `Email` entity represents an email message prepared for delivery.

### Properties

- **Id** (Guid): Unique identifier.
- **OrganizationId** (Guid): Organization that owns the email.
- **UserId** (Guid): User that receives the email.
- **Module** (string): Module that requested the message, such as `iam`.
- **Feature** (string): Feature that requested the message, such as `organizations`.
- **TemplateKey** (string): Template key used to render the email.
- **Recipient** (string): Destination email address. It is stored lowercase and trimmed.
- **Subject** (string): Rendered email subject.
- **Body** (string): Rendered email body.
- **IsHtml** (bool): Indicates if the body contains HTML.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **SentAt** (DateTime?): Date when the email was sent.
- **ExpiresAt** (DateTime): Date when the email can be removed by retention cleanup.
- **Status** (EmailStatus): Current delivery status.
- **RetryCount** (int): Number of failed delivery attempts.
- **NextAttemptAt** (DateTime?): Next retry date.
- **Attempts** (IReadOnlyCollection<DeliveryAttempt>): Delivery failure history.

### Behavior

- `Create` creates a pending email and calculates expiration from retention policy.
- `MarkAsProcessing` marks the email as being processed.
- `MarkAsSent` marks the email as sent and clears the next attempt date.
- `RecordFailure` stores failure details, increments retries, and schedules the next attempt.

## Notification Entity

The `Notification` entity represents an in-app message for a user.

### Properties

- **Id** (Guid): Unique identifier.
- **OrganizationId** (Guid): Organization that owns the notification.
- **UserId** (Guid): User that receives the notification.
- **Module** (string): Module that requested the message.
- **Feature** (string): Feature that requested the message.
- **TemplateKey** (string): Template key used to render the notification.
- **Title** (string): Rendered notification title.
- **Message** (string): Rendered notification message.
- **ActionLink** (string): Optional link related to the notification.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **ReadAt** (DateTime?): Date when the user read the notification.
- **ExpiresAt** (DateTime): Date when the notification can be removed by retention cleanup.
- **Status** (NotificationStatus): Current read status.

### Behavior

- `Create` creates an unread notification and calculates expiration from retention policy.
- `MarkAsRead` marks an unread notification as read and stores the read date.

## Template Entity

The `Template` entity defines reusable message content for one module and key.

Templates are multilingual. Each language is represented by one `TemplateTranslation`. A translation can have email content, notification content, or both.

### Properties

- **Id** (Guid): Unique identifier.
- **Module** (string): Module that owns the template. It is stored lowercase and trimmed.
- **Key** (string): Template key. It is stored lowercase and trimmed.
- **IsAllowingOptOut** (bool): Indicates if users can opt out from this template.
- **Severity** (NotificationSeverity): Importance level for notifications.
- **RetentionPolicy** (RetentionPolicy): Retention policy used by generated messages.
- **Translations** (IReadOnlyCollection<TemplateTranslation>): Language-specific content.
- **CreatedAt** (DateTime): Creation timestamp in UTC.
- **CreatedBy** (Guid): User that created the record.
- **UpdatedAt** (DateTime?): Last update timestamp in UTC.
- **UpdatedBy** (Guid?): User that last updated the record.

### Behavior

- `Create` creates a template and normalizes module and key.
- `Update` changes template metadata.
- `AddTranslation` adds a translation when the language does not already exist.
- `UpdateTranslation` changes an existing translation.
- `RemoveTranslation` removes a translation by language.

## TemplateTranslation Value Object

The `TemplateTranslation` value object stores content for one language.

### Properties

- **Language** (string): BCP 47 language code, normalized by `LanguageOptions`.
- **Name** (string): Display name used when searching templates.
- **Email** (TemplateTranslationEmail?): Email content for this language.
- **Notification** (TemplateTranslationNotification?): Notification content for this language.

### Behavior

- `Create` normalizes language and trims the name.
- `Update` changes name, email content, and notification content.

## TemplateTranslationEmail Value Object

The `TemplateTranslationEmail` value object stores email channel content.

### Properties

- **Subject** (string): Email subject.
- **Body** (string): Email body.
- **IsHtml** (bool): Calculated from the body content.

### Behavior

- `Create` trims subject and detects if body is HTML.
- `Update` changes subject and body, then recalculates `IsHtml`.

## TemplateTranslationNotification Value Object

The `TemplateTranslationNotification` value object stores notification channel content.

### Properties

- **Title** (string): Notification title.
- **Message** (string): Notification message.
- **ActionLink** (string?): Optional action link. Empty values are stored as null.

### Behavior

- `Create` trims fields and normalizes the action link.
- `Update` changes fields and normalizes the action link.

## Enums

### EmailStatus

- **Pending** (1): Email is ready to be sent.
- **Processing** (2): Email is being processed.
- **Sent** (3): Email was sent.
- **Failed** (4): Email failed after retries.

### NotificationStatus

- **Unread** (1): Notification has not been read.
- **Read** (2): Notification has been read.

### NotificationSeverity

- **Information** (1): Informational message.
- **Warning** (2): Warning message.
- **Critical** (3): Critical message.

## Relationships

- **Template to TemplateTranslation**: One template can have many translations. Each translation belongs to one language.
- **TemplateTranslation to Email Content**: Optional one-to-one value object.
- **TemplateTranslation to Notification Content**: Optional one-to-one value object.
- **Template to Email**: Generated emails store `TemplateKey`, not a database relationship.
- **Template to Notification**: Generated notifications store `TemplateKey`, not a database relationship.
- **Organization and User Ownership**: Emails and notifications store `OrganizationId` and `UserId`.

## Design Principles

- **One Request, Multiple Channels**: A user message request can create an email, a notification, or both.
- **Language First**: Template translations are grouped by language.
- **Optional Channels**: If a translation has no email content, Courier can still create a notification. If it has no notification content, Courier can still create an email.
- **No TemplateType**: Channel presence is defined by `Email` and `Notification` properties inside the translation.
- **Retention**: Generated messages calculate `ExpiresAt` from the template retention policy.
- **MongoDB Friendly Shape**: Template translations are nested value objects, avoiding polymorphic discriminators.
- **Read Tracking**: Notifications use `Unread` and `Read`; there is no archive state.
